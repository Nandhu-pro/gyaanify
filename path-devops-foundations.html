What DevOps really means

DevOps is a way of working where the people who build software and the people who run it share responsibility for it. The goal is to deliver changes often, in small pieces, with fewer failures.

It combines culture (shared ownership and learning from mistakes), practices (automation and monitoring) and tools (pipelines, version control and cloud platforms). Tools alone don't make a team DevOps; habits do.

Key takeaways

  • Build and run software as one team
  • Ship small changes often
  • Culture matters as much as tools
Lesson 2 of 42 min read

CI/CD pipelines

Continuous Integration (CI) means every code change is automatically built and tested as soon as it's pushed. Continuous Delivery or Deployment (CD) means changes that pass the tests are automatically prepared for release, or released.

A pipeline is the automated sequence of steps: build, test, scan, package and deploy. Tools such as Azure Pipelines and GitHub Actions describe these steps in a YAML file stored with the code.

Key takeaways

  • CI builds and tests every change
  • CD releases changes safely and automatically
  • Pipelines are defined as code
Lesson 3 of 42 min read

Infrastructure as Code

Infrastructure as Code (IaC) means describing servers, networks and cloud services in files instead of clicking through a portal. Common tools include Terraform and Bicep.

Because the setup is code, it can be reviewed, versioned and repeated exactly. You can create identical test and production environments, and rebuild everything quickly if something breaks.

Key takeaways

  • Describe infrastructure in files
  • Review and version it like code
  • Rebuild environments reliably
Lesson 4 of 42 min read

DevSecOps: security in the pipeline

DevSecOps builds security checks into every step of delivery instead of leaving them to the end. This is often called shifting left.

Typical checks include scanning code for leaked passwords or keys, checking third-party packages for known vulnerabilities, scanning container images, and giving each service only the access it needs. Problems found early are faster and cheaper to fix.

Key takeaways

  • Security is everyone's job
  • Automate scans in the pipeline
  • Grant least privilege
